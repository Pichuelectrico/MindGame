MindGame — Informe técnico para el jurado

Combate táctico 3D con IA local · Categoría CMP (IA, endpoints y videojuegos) · Octubre 2026

Integrantes: Joshua Reinoso

1. Problema

En el discurso actual sobre inteligencia artificial se afirma, con frecuencia, que los modelos de lenguaje (LLM) ya pueden asumir decisiones críticas en tiempo real: reaccionar a un entorno cambiante, elegir la acción correcta y hacerlo a tiempo. Esa afirmación suele evaluarse en demos offline, chatbots o tareas sin presión temporal estricta. Falta un entorno donde el costo de una respuesta tardía sea inmediato y observable.

MindGame plantea esa prueba en un videojuego de combate. El juego ofrece un marco seguro y divertido para medir si un LLM local puede competir —en latencia y calidad de decisión— contra un jugador humano. Para reducir la complejidad de control del modelo, las acciones del combate se simplifican a un catálogo cerrado de decisiones (golpear, esquivar, correr, lanzar, lasers, etc.). Aun así, el combate es en tiempo real y no por turnos: el reloj no se detiene para esperar la red; quien responde tarde pierde la ventana de acción.

2. Relación con la categoría CMP

El proyecto se enmarca en CMP por la conjugación explícita de:

  • Inteligencia artificial generativa (LLM local) aplicada a decisión de agente;
  • Endpoints / integración de sistemas (cliente HTTP asíncrono, telemetría JSONL, dashboard web);
  • Videojuegos como banco de prueba de tiempo real (Unity, combate, UX de comandos).

MindGame no es solo una demo de “NPC inteligente”: es un experimento controlado sobre los límites de latencia y control cuando un modelo de lenguaje debe actuar bajo las mismas reglas que un jugador humano.

3. Solución y cómo funciona

El prototipo está construido en Unity 6000.6.5f1 (URP). La arquitectura separa dos capas: una de plan (qué acciones ejecutar, a partir de texto, rueda de cartas o respuesta del LLM) y una de ejecución (cómo animar, mover y aplicar daño). Todos los personajes, incluido el del jugador, son controladores autónomos; el humano solo dicta o selecciona el plan del avatar principal.

3.1 Interacción del jugador

  • Modo Manual: movimiento y acciones inmediatas (teclado/ratón).
  • Modo Comandos: pausa lógica activa y rueda radial de cartas para armar un plan corto (hasta 6 acciones) sin escribir texto libre.

3.2 El jefe (boss) y la IA

El boss se conecta a un LLM local vía HTTP (Ollama; en las pruebas se usó qwen2.5:7b). Hay tres modos de decisión, conmutables en juego: LLM directo (el modelo responde con un plan de acciones por petición), Heurístico / BotBrain (algoritmo local sin red) y Estratega (el LLM elige cada ~6 s una personalidad Distance / Fighter / Normal; el algoritmo ejecuta la táctica en tiempo real). Complementan la experiencia el modo Furia (<30 % HP), ataques láser recto y láser tornado con telegrafía, orbes de vida y un dashboard web sobre el log JSONL de decisiones.

4. Resultados / estado actual

Las pruebas de combate contra un usuario real en Game Mode muestran un patrón claro y repetible: el LLM puede predecir acciones útiles —es decir, “entiende” el estado y propone planes coherentes con el catálogo—, pero entrega las respuestas tarde respecto al ritmo del combate. En un videojuego de acción continua, la ventana útil para esquivar un golpe, cerrar distancia o lanzar un laser se mide en décimas de segundo. Si la decisión llega después de esa ventana, el plan correcto llega cuando el contexto ya cambió: el jugador se movió, el cooldown expiró o el daño ya se aplicó.

Ese desfase no es un fallo puntual de una sola petición. Incluso con endpoint local (sin red pública), la latencia de inferencia del modelo suele situarse en cientos de milisegundos por decisión. En contraste, el heurístico BotBrain responde en el mismo tick del motor: órdenes de magnitud más rápido, porque no serializa contexto a texto, no espera HTTP ni parsea una respuesta libre. Frente al ciclo de combate, esa diferencia es la que decide si el jefe “reacciona” o “parece distraído”.

Métrica orientativa (telemetría del prototipo, log de decisiones). Sobre una muestra del archivo llm-decisions.jsonl del proyecto: decisiones etiquetadas como LLM (n≈46) con mediana ≈ 426 ms y p90 ≈ 578 ms; decisiones heurísticas (n≈438) con latencia reportada ≈ 0 ms (decisión local inmediata). Valores de sesión de desarrollo; no sustituyen un banco formal, pero ilustran el gap temporal entre “pensar con el modelo” y “actuar con el algoritmo”.

La alternativa Estratega —el algoritmo gestiona la táctica frame a frame y el LLM solo actualiza la estrategia vigente cada ~6 s— responde mejor a las acciones del jugador en tiempo real. Conserva algo del “juicio” del modelo (qué estilo de pelea adoptar) sin pagar el costo de una inferencia por cada golpe. En la práctica, el jefe deja de “congelarse” esperando al LLM y mantiene presión táctica coherente con la personalidad elegida (mantener distancia, pelear de cerca, o un equilibrio Normal).

En síntesis del estado actual del prototipo: el LLM es útil como capa de intención o de reorientación estratégica; el algoritmo local es quien sostiene la acción bajo presión temporal. Usar solo el LLM como controlador de cada acción no alcanza, hoy, el umbral de reactividad que exige un combate continuo contra un humano.

5. Conclusiones

A octubre de 2026, en este entorno de combate continuo, la inteligencia artificial generativa aún no es, por sí sola, la primera opción fiable para eventos que exigen acción en tiempo real en videojuegos. La razón principal no es la “falta de inteligencia” del modelo —el LLM predice planes razonables—, sino el coste temporal de producir esa predicción: cientos de milisegundos por decisión frente a un ciclo de juego que no espera. En otras palabras: el modelo llega a una buena respuesta, pero llega tarde para el instante en que esa respuesta importaba.

El algoritmo local responde a tiempo precisamente porque evita esa cadena (prompt → HTTP → inferencia → parseo). Opera sobre reglas y sensores ya disponibles en memoria del proceso Unity, con latencia despreciable respecto al frame. Por eso el modo Estratega funciona mejor como arquitectura de compromiso: el LLM aporta variedad y criterio a baja frecuencia; el BotBrain garantiza reactividad a alta frecuencia.

Implicación para el estado del arte que se discute en CMP: conviene distinguir capacidad de razonar un plan de capacidad de ejecutarlo bajo deadline de tiempo real. MindGame sugiere que, en 2026, el valor práctico de un LLM en combate aparece cuando se usa como capa de estrategia o supervisión, y un sistema determinista ejecuta la táctica bajo presión temporal —no cuando se pretende que el modelo sea, solo, el controlador de cada acción del agente.
